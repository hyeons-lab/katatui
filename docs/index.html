Build Idiomatic TUIs with
Kotlin & Ratatui

Katatui provides high-performance, cross-platform terminal UI components powered by the world-class Ratatui engine, wrapped in a pure Kotlin DSL.

Get Started Explore Sample App
Main.kt 
fun main() = terminal {
    draw {
        block { 
            area = size
            style = Style(bg = Color.Rgb(41u, 44u, 51u)) 
        }

        val rows = Layout.vertical(
            Constraint.Length(3), Constraint.Fill(1)
        ).split(size)

        tabs(rows[0]) { /* ... */ }

        val sections = Layout.vertical(
            Constraint.Length(5), Constraint.Fill(1)
        ).split(rows[1])

        sparkline(sections[0]) { /* ... */ }

        val cols = Layout.horizontal(
            Constraint.Percentage(45), Constraint.Fill(1)
        ).split(sections[1])

        gauge(cols[0]) { percent = 42u }
        barChart(cols[1]) { bar("Rust", 82u) }
    }
    poll()
}

True Multiplatform DSL

Write your UI once, use it from Kotlin or Swift with native ergonomics.

Kotlin DSL 
terminal {
    draw {
        block {
            title = "Dashboard"
            borders = Borders.all
        }
        
        paragraph {
            text = "Hello from Kotlin!"
            area = size.inner()
        }
    }
}
Swift DSL 
Katatui.terminal { t in
    t.draw { frame in
        frame.block { b in
            b.title = "Dashboard"
            b.borders = Borders.all.bits
        }

        frame.paragraph { p in
            p.text = "Hello from Swift!"
            p.area = frame.size.inner()
        }
    }
}

Core Principles

Why choose Katatui?

Kotlin & Swift DSLs

Built from the ground up to feel native. Use idiomatic lambdas, sealed classes, and properties in both Kotlin and Swift.

Ratatui Engine

Leverage the battle-tested performance and widget library of Ratatui. It's the same engine powering the best CLI tools in the industry.

Swift Interop with SKIE

Powered by SKIE, Katatui provides native Swift enums and sealed class bridging, making it feel like a pure Swift library.

The Katatui Difference

We've translated Rust's patterns into idiomatic Kotlin paradigms that feel natural to JVM and KMP developers.

Feature Ratatui (Rust) Katatui (Kotlin)
Swift Interop Opaque pointers / C ABI Native Enums via SKIE
Widget Definition Block::default().title("T") Block { title = "T" }
Memory Management Ownership / Borrowing AutoCloseable / use { }
Layout API Builder chaining Vararg DSL constructors
Event Handling Match on Enums When on Sealed Classes
Cleanup Explicit restore() Automatic via Closeable

Native Performance Everywhere

Katatui targets desktop platforms where TUI development shines. No runtime required, no GC pauses in the rendering loop, just raw native speed.

Get Started

1 Add Dependency 

// build.gradle.kts
kotlin {
    sourceSets {
        nativeMain.dependencies {
            implementation("com.hyeons-lab:katatui:0.1.0-SNAPSHOT")
        }
    }
}

2 Build FFI (Local Development) 

# Build Rust FFI for your architecture
cd katatui-ffi
cargo build --release --target aarch64-apple-darwin

3 Run Sample App 

# From root directory
./gradlew :sample-app:runDebugExecutableMacosArm64
